# Baseline profile — the classes and methods ART compiles ahead of time at
# install, instead of interpreting them until the JIT gets around to it.
#
# This matters more for a keyboard than for most apps. The IME process is
# started, killed and started again all day: the system reclaims it whenever
# the keyboard is hidden and memory is short, so a phone that is under pressure
# — which is exactly the low-end phone this is for — pays the warm-up cost over
# and over rather than once. Without a profile of its own the app shipped 4459
# profile entries, every one of them from Compose and Coil and none from this
# codebase, so the keyboard's own service, renderer and decoder ran interpreted
# on each of those starts.
#
# Rules are `flags` + a class/method pattern. `H` marks a method hot, `S` marks
# it as running during startup, `P` post-startup; `**` is expanded against the
# real dex at build time by AGP, and R8 rewrites the names to match the
# minified build, so the original names below are the right ones to write.
#
# Scope is deliberate rather than "everything". Compiling the whole app would
# grow the installed .odex and the install itself, which is a poor trade on a
# device short of storage — the same devices the `lite` flavor exists for. What
# is listed is the keyboard runtime and the modules it loads to draw a key and
# answer a keystroke. The settings app's screens, and the tool subsystems that
# only wake when their tool is opened (ML Kit, Whisper, the local LLM, the
# grammar checker, plugins, addons), are left out on purpose: they are not on
# the path between tapping a text field and seeing a letter.
