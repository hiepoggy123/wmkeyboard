Every height, width and gap on WM Keyboard is a slider, not a fixed number: you can shrink it toward one thumb, split it down the middle for a wide screen, or detach it into a floating panel entirely. Sizing you set for portrait carries over everywhere by default, but landscape and unfolded screens can each override it, right down to scaling the whole keyboard at once.

## Sizing the keys

<SettingsPath path="Layout & size / Size & position / Key height" />

**Key height** sets the height of every key row and, with it, the overall input height: a slider from 32dp to 100dp, default **48dp**. The emoji, clipboard and snippet panels scale with this value too, so a taller keyboard also means taller panels.

**Bottom row height** gives the spacebar and <KeyCap>Enter</KeyCap> row its own height, independent of the letter rows: a slider from 0dp to 96dp. At 0 (the default) it shows "Follow keys" and just matches the letter rows; raise it for an easier-to-hit spacebar without growing the whole keyboard. A custom layout that sets its own row heights ignores this slider.

**Key spacing** adjusts the gap around every key, from 0% to 200%, default **100%**. Higher spreads the keys apart (and makes the keyboard a little taller, since the gap is part of each row); lower packs them tighter.

If you've turned on <SettingsPath path="Layout & size / Number row / Number row" /> (its own group at the top of this same screen, above Size & position), it gets its own **Number row height** slider too, 32dp to 100dp, default **42dp**, independent of the letter keys.

The size of the labels printed on the keys is a separate slider (**Key label font size**) under <SettingsPath path="Appearance / Key label font size" />, 0.7× to 1.5×, default **1.0×**. It isn't part of this settings group, but the [per-screen sizing](#sizing-each-screen-shape) below can still override it per screen shape.

## Narrowing and repositioning it

<SettingsPath path="Layout & size / Size & position / Keyboard width" />

**Keyboard width** shrinks the keyboard horizontally instead of spanning the full screen, from 50% to 100%, default **100%**. Below 100%, a **Keyboard position** choice appears, Left, Center (the default), or Right, to pick which edge the narrowed keyboard hugs. This is a permanent dock; [one-handed mode](#one-handed-mode) below is described in its own info text as "a quick preset that overrides this while active," without changing the stored width or position.

**Side padding** shaves an equal margin off both edges, narrowing the keys toward the middle for thumb reach, without docking to one side the way one-handed mode does. It's a slider from 0% to 30%, default **0%**, and stacks on top of keyboard width: set both, and the keyboard is first narrowed to the chosen width, then padded in further from each side of that.

**Bottom padding** raises the whole keyboard away from the bottom edge and the gesture navigation bar, from 0dp to 40dp. The default depends on your Android version: **32dp** on Android 15 and up, where the IME window can draw behind the gesture bar, and **8dp** on older versions. Raise it if the bottom row feels cramped against the screen edge or you keep triggering system navigation by mistake.

## Sizing each screen shape

<SettingsPath path="Layout & size / Per-screen sizing" />

Portrait is the base size: everything in the two sections above. Three other screen shapes can each override any of that: **Landscape**, **Portrait, unfolded**, and **Landscape, unfolded**. Whatever you leave untouched on an override just follows portrait, so tuning one shape never requires setting up the rest.

"Unfolded" isn't read from a fold sensor: it's decided by the screen's smallest dimension being at least 600dp, checked live as the configuration changes. That deliberately catches a phone turned sideways as still "not unfolded" (it's wide but still a phone), while catching a genuinely large screen (an opened foldable's inner display, or a tablet that was never foldable at all) as "unfolded" either way it's held. There's no separate "folded" state in the code; portrait's values are what a folded or ordinary phone always used. The settings screen's own caption calls portrait your "folded" size for exactly that reason.

Tap a shape's row to expand its editor:

- **Keyboard scale** — a whole-keyboard multiplier, 50% to 150%, that only exists on these three override shapes; there is no base scale for portrait itself. It multiplies key height and number row height together, so a foldable's roomy inner display can run a smaller keyboard than its cover screen (or the reverse) without re-dialing each height by hand.
- **Key height**, **Number row height** (if the number row is on), **Bottom padding**, **Keyboard width**, **Font size**, and, when width is under 100%, **Keyboard position** — the same ranges as their portrait counterparts above.
- **Follow portrait again** — appears only once a shape has at least one override set, and clears every override for that shape in one tap.

Key spacing, side padding, bottom row height, and everything in [one-handed, split and floating](#one-handed-mode) below are global instead: they apply the same regardless of which screen shape you're on.

## One-handed mode

<SettingsPath path="Layout & size / One-handed, split & floating / One-handed mode" />

**One-handed mode** shrinks the keyboard toward one edge for reach with a single thumb: Off (the default), Left, or Right. Unlike the per-shape sizing above, it's tuned separately per **orientation** (Portrait and Landscape), not per fold state, since a one-handed keyboard cares about which way you're holding the phone, not whether it's unfolded.

Each orientation gets its own three controls:

- **Width** — the keyboard's share of the screen while one-handed is active, 40% to 85%. Default is **78% in portrait**, **55% in landscape**: landscape starts narrower because a landscape keyboard is already very wide, so 78% there would barely help.
- **Height** — scales the key height down for reach, 60% to 100%, default **100%** in both orientations.
- **Side** — which edge it docks to, Left or Right, default **Right** in both orientations.

<PhoneFrame caption="One-handed mode docked to the right edge, with the flip and exit rail.">
  {/* shot: typing/size-position-one-handed */}
</PhoneFrame>

On the keyboard itself, a narrow rail fills the space one-handed mode leaves behind, with two buttons: an arrow that flips the keyboard to the other edge (live, and remembered as that orientation's new default side) and a fullscreen icon that exits one-handed mode entirely. If you've pinned the **One-handed** tool to your toolbar, tapping it toggles one-handed on using that orientation's preferred side, or off if it's already on. It has no default letter binding on a physical keyboard, but the leader key still reaches it (bind it a letter in **Tool shortcuts list**, or press <KeyCap>T</KeyCap> for the toolbox if you've pinned it there); see [Hardware keyboards](/typing/hardware-keyboard/).

## Splitting the keyboard in half

<SettingsPath path="Layout & size / One-handed, split & floating / Split keyboard" />

**Split keyboard** divides every row down the middle with a gap between the halves, so your thumbs travel less on a wide screen: most useful on tablets, foldables, and phones turned to landscape. It's off by default; turn it on and a **Split gap** slider appears, 5% to 40% of the keyboard's width, default **12%**. A bigger gap pushes the halves further toward the edges but narrows each key. The spacebar splits between the two halves along with everything else, and (like one-handed mode) the setting is global rather than tied to a particular screen shape.

## Floating the keyboard

<SettingsPath path="Layout & size / One-handed, split & floating / Floating keyboard" />

**Floating keyboard** detaches the keyboard from the bottom of the screen into a small, movable panel that hovers over whatever app is open. It's off by default; turn it on and a **Floating keyboard width** slider appears, 240dp to 500dp, default **320dp**. The panel's own resize grip shares its 240dp floor, but not its ceiling: see the edge case below. There's no separate height slider; height is drag-only, clamped between 60% and 160% of the keyboard's normal height.

The panel's handle bar carries three controls, left to right:

- **Dock button** — a fullscreen icon that returns the keyboard to its normal, docked position.
- **Drag pill** — dragging anywhere across the middle of the handle bar, not just the small pill drawn there, moves the panel. Its position is saved as a fraction of the free space around it rather than a pixel coordinate, so it survives rotation; by default that's centered horizontally and pinned to the bottom of the available space.
- **Resize grip** — drawn as two short diagonal lines rather than a diagonal-arrows icon, deliberately, so it doesn't read as another fullscreen button. Dragging it resizes width and height together: width tracks your finger directly, height tracks it inverted, because the grip sits on the panel's *top* bar: drag up to grow the panel, down to shrink it.

<PhoneFrame caption="The floating panel's handle bar: dock button, drag pill, and resize grip.">
  {/* shot: typing/size-position-floating */}
</PhoneFrame>

Floating mode replaces the normal layout logic rather than combining with it. While it's on:

- The one-handed rail and edge-docking don't render: your one-handed setting is untouched but has nothing to apply to.
- Keyboard width, keyboard position, and bottom padding from the sections above don't apply either; the panel's size and position come entirely from its own width slider, drag position, and resize grip.
- **Split keyboard still works while floating**: the two features aren't mutually exclusive, since split rendering happens inside the same keyboard body the floating panel wraps.

Touches outside the panel pass straight through to the app underneath it, and the keyboard forces full-screen (extract) mode off for as long as it's floating. If you've pinned the **Floating** tool to your toolbar, tapping it toggles floating on or off directly.

## Details & edge cases

- **Keyboard scale has no portrait equivalent.** It only exists on the three override screen shapes; portrait is sized entirely by its own key-height and number-row-height sliders, with no multiplier on top.
- **"Unfolded" is a screen-size check, not a fold-sensor read.** Any device with a smallest dimension of 600dp or more counts, including a tablet that never folds; the label describes what the screen currently looks like, not the hardware.
- **One-handed mode's width setting is a live override, not a rewrite.** Turning it on temporarily overrides the keyboard-width and position settings while active; turning it off returns to whatever those were set to.
- **A very wide screen can let the floating panel's resize grip briefly exceed 500dp mid-drag.** It snaps back to the 500dp maximum once you release it.
- **No edition split.** Every setting on this page (sizing, one-handed, split, and floating) works identically on the full and lite builds.

For haptics and sound on each keystroke, see [Sound & vibration](/typing/feedback/). For the physical-keyboard leader key that can toggle one-handed, split, and floating without touching the screen, see [Hardware keyboards](/typing/hardware-keyboard/).
