The AI tool runs a fixed set of one-tap writing actions — rewrite, summarize, translate, and more — against whatever text is in the field you're typing in. Where those actions actually run is up to you: a cloud provider with your own API key, a self-hosted Ollama or LM Studio server on your network, or a model that downloads once and answers entirely on the device.

## Using it

Open **AI** from the [toolbar or the toolbox](/tools/overview/) — it isn't pinned by default, so the first time you'll likely reach it through the toolbox, by typing its `ai` keyword on the suggestion strip, or, on a hardware keyboard, through the [leader key](/reference/shortcuts/): double-tap <KeyCap>Ctrl</KeyCap>, then press <KeyCap>A</KeyCap>.

The panel opens on a row of action chips:

- **Rewrite**, **Summarize**, **Translate**, **Improve**, **Fix grammar**, **Explain**, **Continue** — each needs text to work on and is greyed out on an empty field.
- **Custom** — the one chip that stays live on an empty field. Tapping it opens an instruction box on the keyboard itself; whatever you type is the prompt for that run, so it can write brand-new text from nothing rather than transform existing text.

If nothing is configured yet, the panel shows a short explanation instead of the chip row: an **Open settings** shortcut if no provider is set up (the default on a fresh install), or a **Download a model** shortcut if On-device is selected but nothing has been downloaded yet.

<PhoneFrame caption="The empty state shown before any provider or local model is set up.">
  {/* shot: tools/ai-need-setup */}
</PhoneFrame>

**What gets sent:** selected text wins if you've selected any; otherwise the whole field. **Continue** is the exception — it always uses the text before the cursor (up to 4,000 characters), since continuing needs to know what came before, not what comes after. Tapping a chip on a truly empty field (and no selection) shows "Nothing to work on — type some text first" instead of sending a request.

While a request is running, the panel reports which step it's on — Preparing, Connecting, Waiting for the model, and Reasoning for a model that thinks before answering — rather than a bare spinner, since a request can spend most of its time waiting on a slow connection or a long field.

Once a result streams in, two buttons commit it: **Replace** swaps the field's text for the result, and **Insert** drops it in at the cursor instead. Continue is the one exception to Replace: since deleting the text you just asked it to continue would defeat the point, Replace appends there rather than overwriting. A **strip markdown** checkbox (checked by default when the result contains any) removes headings, bullets, quotes, code fences/inline code, links, and bold/italic syntax from what gets committed; unchecking it keeps the raw markdown. Reasoning output between `<think>` tags is filtered out of both Replace and Insert either way — only the answer itself lands in your field.

## Choosing where it runs

A row of provider chips sits at the top of the tool's settings: **Claude**, **OpenAI**, **Gemini**, **Ollama**, **LM Studio**, and **On-device** — you're not limited to picking one forever, switching providers is just another tap.

<PhoneFrame caption="The provider row and a cloud provider's API key and model fields.">
  {/* shot: tools/ai-settings-providers */}
</PhoneFrame>

### Cloud providers

Claude (Anthropic), OpenAI, and Gemini are bring-your-own-key only — WM Keyboard ships no built-in or proxied key for any of them, unlike some of the other network tools. Paste your own key into the provider's field:

- **Claude** — from `console.anthropic.com` → API keys
- **OpenAI** — from `platform.openai.com` → API keys
- **Gemini** — has a free tier at `aistudio.google.com`

Each provider also has a **Model** field; leave it blank to fall back to the app's built-in default — `claude-sonnet-5` for Claude, `gpt-5.6-luna` for OpenAI, `gemini-3.5-flash` for Gemini — shown right in the field's hint, so fill in a model name here if you want something else.

### Self-hosted servers

**Ollama** and **LM Studio** point at a server on your own network instead of a cloud API — no key needed, just an address like `http://192.168.0.10:11434` (Ollama) or `http://192.168.0.10:1234` (LM Studio). Ollama needs `OLLAMA_HOST=0.0.0.0` set so it listens beyond localhost; LM Studio needs its local-server option turned on. Both fields are blank by default. Ollama defaults its model field to `qwen3` when left blank; LM Studio has no default model to fall back to — it uses whatever model the server currently has loaded.

:::note
Traffic to a self-hosted server is plain HTTP, and the app allows cleartext traffic app-wide to support it. Keep the server on a network you trust.
:::

### Local models

<Flavor edition="full" />

The **On-device** provider runs a model entirely on the phone, no network involved. It's the only provider option that needs a download first, and it's the one provider chip that doesn't appear at all in a Lite build.

<PhoneFrame caption="The on-device model catalog, with tier badges and a params/size subtitle per model.">
  {/* shot: tools/ai-settings-local-catalog */}
</PhoneFrame>

The catalog is eight models, ordered best-first rather than smallest-first:

| Model | Params | Size | Tier | Gated |
|---|---|---|---|---|
| Gemma 4 E2B | 2B | 2.59 GB | Recommended | |
| Gemma 4 E4B | 4B | 3.66 GB | Recommended | |
| Gemma 3 1B | 1B | 584 MB | Untested | Yes |
| Qwen 2.5 1.5B | 1.5B | 1.6 GB | Standard | |
| Qwen 3 0.6B | 0.6B | 347 MB | Experimental | |
| Qwen 2.5 0.5B | 0.5B | 546 MB | Experimental | |
| Gemma 3 270M | 270M | 304 MB | Untested | Yes |
| SmolLM2 135M | 135M | 143 MB | Experimental | |

"Gated" models (2 of the 8) need a Hugging Face account: paste a token into the **Hugging Face token** field above the catalog and accept the model's license on its Hugging Face page once. Every model also carries an advisory minimum-RAM figure behind the scenes: the app appends "May be too large for this device" to a model's subtitle when your phone's total RAM falls under it, but it never blocks the download outright and never shows the raw RAM number. That comparison is the only per-device signal the catalog gives you up front — there's no published speed benchmark, since how fast a model actually responds depends on the phone as much as the model, and a progress readout with elapsed seconds is what you get once a request is running rather than an estimate beforehand.

Tapping **Download** starts a resumable download — cancel it, lose signal, or background the app, and resuming picks the transfer back up from where it left off rather than restarting. Only one download runs at a time. A model 500 MB or larger asks for confirmation first if you're on a metered connection.

Don't need the catalog? **Import your own** takes any `.litertlm` or `.task` file — the two container formats the on-device engine actually loads — for instance one you converted yourself or downloaded elsewhere in a browser. There's no GGUF support; a file with any other extension is rejected on import.

A **Compute** row picks **CPU** or **GPU** for inference; CPU is the default. GPU is best-effort: if it fails to initialize, or crashes partway through an answer, the engine falls back to CPU on its own and remembers not to retry GPU for that model file again this session.

## Options

<SettingsPath path="Tools / AI writing tools" />

Like every tool, AI has an **Enabled** toggle (on by default) and, if [colorful tool icons](/reference/settings/tools/) are on, a per-tool icon color override. Below that:

- **Keyword** — the word that offers this tool on the suggestion strip when you type it alone; defaults to `ai`.
- **Provider** — which of the six providers above is active; defaults to **Claude**, though with no key entered yet a fresh install lands on the empty-state screen until you add one.
- **Max response length** — a token ceiling, roughly ¾ of a word each; default **2,048**, adjustable from 256 to 8,192. Hidden for the On-device provider, whose ceiling is the local model's own context window instead. A model the app guesses is a reasoning model (by a substring match against its model ID, e.g. containing "thinking" or "qwen3") automatically gets 4× this ceiling, capped at 32,768, since reasoning tokens are spent from the same budget before the answer even starts.
- **Translate action's target language** — free text, defaults to **English**.
- **Show model reasoning** — off by default. Turning it on streams a reasoning model's raw `<think>` passages instead of the step-by-step progress readout.
- **Model picker on the panel** — on by default. Adds a horizontally-scrolling row to the panel itself for switching between every configured provider and downloaded local model in one tap — it's hidden automatically whenever there are fewer than two to choose from.
- **Prompts** — one editable system prompt per action (Custom excluded, since its instruction comes from you each run). Clearing a field restores the built-in prompt for that action.

## What leaves your phone

The panel itself sends nothing until you actually tap an action chip — opening the tool, or typing in the field behind it, sends nothing anywhere on its own.

- **On-device**: the text you run an action on never leaves the phone. Response length is bounded by the local model's own context window instead of a server-side limit.
- **Any other provider** — cloud or self-hosted: the text you run an action on is sent to that provider, only at the moment you tap the action. API keys and server addresses are stored on the device, not in any WM Keyboard service. See [Privacy at a glance](/privacy/overview/) for how this fits the keyboard's broader per-tool approach to anything that leaves the device.

## Details & edge cases

- **AI isn't pinned to the toolbar or the onboarding wizard's starter set by default** — you add it yourself from the toolbox once you want it, the same as most non-essential tools.
- **Not available on the lock screen.** AI needs credentials the direct-boot-safe mirror of your data deliberately doesn't carry, so it's one of the tools that only works after you've unlocked the device once since restart.
- **The Writing keyboard mode pins AI first** on its toolbar for apps it recognizes as writing-heavy — see [Keyboard modes](/typing/modes/). The pin shows in both editions, same as the tool itself; only the On-device provider is Full-only.
- **A reasoning model's guess is just a substring match** against the model ID (things like "thinking", "-r1", "qwen3", "gpt-5"), so it can be wrong in either direction — a false positive only costs a larger token ceiling, a false negative risks a response that gets cut off mid-thought.
- **Custom has no stored default prompt.** Every other action's prompt can be edited but always has a built-in fallback; Custom's instruction only ever exists for the run you type it for.
- **Local models are advisory about RAM, never a hard gate.** A phone under a model's stated minimum can still download and run it — you just get a warning in the catalog first.
- **No shared or built-in key for any cloud provider.** Every one of Claude, OpenAI, and Gemini requires your own API key; there's no free built-in quota the way some of the other network tools offer.
